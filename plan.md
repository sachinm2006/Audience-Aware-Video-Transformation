# NOVA — Audience-Aware Video

## Implementation and design plan

### Product scope and implementation approach

Build a responsive, desktop-first Next.js App Router application in TypeScript and Tailwind CSS, with the 4-step workflow visible across the app: **Upload & Setup → AI Processing → Review & Edit → Final Output**. The sidebar provides **New Transformation, My Projects, Versions, Settings**. The complete upload, processing, review, output, library and settings screens are reachable through the interface and normal workflow transitions.

The frontend will use a typed domain model for uploaded recordings, audience goals, desired durations, processing stages, edit-plan segments, protected-context warnings, approval/render states, and audience versions. The API boundary in `lib/api.ts` supports the concepts in the brief—upload, analyze, processing status, edit plan, approval, render, and versions—without assuming a FastAPI endpoint contract. The provisional adapter validates upload IDs, plan structure, segment ordering/ranges, ContextGuard data and returned video URLs at runtime before the UI trusts them. An environment-configured API base URL will enable a real FastAPI adapter; when no service is configured, a structured mock adapter provides upload, processing, edit-plan, ContextGuard, approval, rendering and output responses. Sample/library plans remain on the demo adapter even if FastAPI is configured, so synthetic IDs and plans are never submitted to the backend. A one-shot `?mockError=upload|analyze|approve|render` URL flag exercises each retry path. Mock results are identified as demonstrations rather than claimed as real AI analysis. In demo mode, downloading an actual rendered video is not represented as available unless the service returns a real output file; the user can still inspect and download the structured sample edit plan. Local video selection creates an actual browser preview and reads real duration, resolution and file size; metadata/error events are bound to a unique source ID so late events from a replaced file are ignored. Upload validation enforces the specified formats, 2 GB size limit and 2-hour duration limit. Timeline seeks selected before the original player's metadata is ready are queued and clamped once metadata loads. The sample edit-plan generator guarantees positive chronological ranges even for recordings shorter than its 14 example segments.

The review workspace will show original/proposed players, a timestamped clickable keep/remove/context-risk timeline and segment list, concise audience-focused explanations, and a compact ContextGuard safeguard. A segment selection synchronizes the highlighted timeline range, original-player timestamp and explanation; when source metadata is pending, the seek is queued. Users can keep/restore any segment, retain protected context, override a warning, approve the plan, and continue to a final-output state. Any removal carrying a context risk requires an explicit override; malformed removed-but-not-overridden context remains unresolved. Versions created from the review/output flow retain the original recording as their source and are represented independently by audience and output duration. API failures will have a concise recovery path and retry. No login, database, or managed backend is required for this frontend-first stage; existing config has both off. Do not add any features excluded by the brief.

Add the newly specified scroll-first public landing page at `/` while preserving the existing NOVA application at `/app` without redesigning its screens. Keep Sign In and product CTAs routed to `/app`; do not invent authentication. Reuse the existing stack, wordmark, typography, tokens, styling system and read-only same-origin app preview; add no runtime packages. The reference video mentioned by the brief was not present in the supplied workspace, and the user explicitly approved proceeding from the written brief alone. Use that written composition and transition sequence as the visual basis; do not claim to reproduce visual details from an unseen video. Create four original, text-free visual assets for the site: one wide source-recording still and three distinct, fictional audience portraits, generated for NOVA and used via their returned project-managed `/manus-storage/async-images/…` URLs as small floating thumbnails rather than large decorative cards.

A central source-video still is the dominant object, surrounded by restrained customer, employee and investor portrait/video thumbnails with small labels, never giant cards. Different audiences need different things.”: copy translates upward and scales down, the source remains anchored before shrinking, audience thumbnails converge toward it and spread to audience positions, and the problem/needs text enters without an abrupt section replacement. ### Project structure

The initialized workspace was empty. Its delivered structure is:

- `app/` — public landing page at `/`, the unchanged four-step product at `/app`, root layout and route-specific metadata.
- `components/landing/` — compact public navigation, responsive scroll-linked hero and audience scenes, source-to-version transitions, AI-understanding sequence, ContextGuard/product-review morph, use-case story and same-origin product preview.
- `components/` — existing application shell/navigation; setup/upload; processing; video player; review/timeline/ContextGuard; output/version history; library; settings; and confirmation dialog, preserved without redesign.
- `lib/types.ts`, `lib/api.ts` and `lib/context-guard.ts` — shared domain/API contracts, runtime-validated browser-side FastAPI/demo adapters and the common protected-context resolution rule.
- `lib/sample-data.ts`, `lib/format.ts` and `lib/download-plan.ts` — audience-edit fixtures with short-source-safe ranges, time/file-format helpers and honest sample-plan download.
- Generated source still and three text-free audience portraits — original generated assets served through project-managed storage URLs; `public/manus-routes.json` and `public/nova-mark.svg` — route manifest for `/` and `/app`, plus NOVA project-logo asset.
- `README.md`, `app.config.ts`, `next.config.ts` and `TODO.md` — frontend/FastAPI handoff, project metadata, static-export configuration and product outcome tracker.

Dependencies are limited to Next.js, React, TypeScript, Tailwind CSS and Lucide; workflow state uses React rather than an additional state library. The Next.js build emits a static site in `out/` for browser-side API integration; Preview runs the development server on configured port 3000 at `0.0.0.0`. No backend, login, database or external storage service is assumed: the browser holds the selected recording for the active session, while the typed adapter stays ready for the eventual FastAPI contract.

### Design system

- **Design Movement:** restrained editorial SaaS, with the precision and quiet confidence of Linear/Stripe-style enterprise software rather than a generic AI dashboard.
- **Core Principles:** clarity before decoration; one source can branch to audience-specific outcomes; explicit human control; meaning-preserving safeguards.
- **Color Philosophy:** white and soft neutral surfaces keep long editing tasks calm; charcoal carries hierarchy; muted gray recedes; one restrained cobalt-blue accent communicates the current step and primary actions. Context risk uses a neutral warm-gray treatment and small icon rather than an alarm banner. Avoid gradients, neon and colorful decoration.
- **Layout Paradigm:** the public page centers one source-video object and oversized editorial typography, then transforms the same scene through sticky, asymmetrical scroll chapters; legible static copy accompanies every moving state. The existing app retains its narrow persistent navigation rail, workflow stepper, expansive work canvas and focused review comparison.
- **Signature Elements:** the compact NOVA frame-mark; three small audience portraits orbiting and then branching from one source-recording still; transcript/qualifier fragments morphing into a review timeline with a restrained ContextGuard marker.
- **Interaction Philosophy:** scrolling progressively explains what changes in the recording; section links and CTAs work as normal keyboard-accessible links; review before committing; segment actions remain reversible; warnings offer specific actions; no internal AI reasoning or prompts.
- **Animation:** one continuous scroll-told film; coordinate the hero text's upward scale-down, anchored source still, portrait convergence/spread, branch paths, processing phrases, qualifier risk/restore, transcript-to-timeline morph, timeline-to-version expansion and final logo/statement echo. Prefer sticky positioning, transform/opacity and a requestAnimationFrame-throttled listener; blur remains very subtle and transition-only. No bounce, spinning, random floating, ubiquitous parallax, dramatic zoom, constant motion or generic fade-in between unrelated sections. Honor reduced motion, simplify tablet and make mobile sequential.
- **Typography System:** reuse the app's modern sans-serif base, with a large centered editorial display tier for hero and story statements and compact system-monospace timestamps. Keep headlines oversized, short and high-contrast; paragraphs concise, line lengths readable and whitespace generous. The visual story must still scan from the headlines; no decorative fonts.
- **Brand Essence:** “One source recording, shaped for the audience who needs it.” For teams who reuse video to explain clearly without losing meaning. Personality: **clear, careful, capable**.
- **Brand Voice:** direct and calm, describing decisions and next actions without hype. Examples: “One recording. Every audience. Same meaning.” / “Review what’s kept, what’s removed, and why.”
- **Wordmark & Logo:** a precise NOVA wordmark paired with a distinctive frame/ribbon glyph built from three offset horizontal strokes, suggesting one recording becoming audience-specific cuts; use the mark consistently in navigation and as the platform project logo.
- **Signature Brand Color:** restrained cobalt blue (`#315FE8`), reserved for interactive focus, selected timeline segments and the current workflow step.

### Frontend/backend boundary

The app reads the optional `NEXT_PUBLIC_API_BASE_URL` from browser-safe build configuration; with static export, set this value when building the deployment bundle, and never use it for secrets. Endpoint paths and response shapes are centralized in `lib/api.ts`, but treated as a proposed adapter contract rather than guaranteed server routes: upload, analyze, approve and render are wired; processing-status and persistent version endpoints await the actual FastAPI contract. API responses are checked at runtime, and sample/library plans always use the local demo adapter even when an API URL is configured. With no base URL, the UI uses the structured mock adapter and marks sample/edit/render state clearly. With a real adapter response, its validated edit plan and downloadable render take precedence. Uploaded video object URLs are temporary browser previews, not durable storage. The public landing page is a static-friendly client component; its `/app` preview and navigation use same-origin relative paths. The project will not invent backend endpoints, persist recordings, or claim that a render was produced when the API has not returned a file.

### Motion system and accessibility

Use CSS transitions/keyframes, restrained transforms, opacity, subtle blur-to-sharp and controlled clip/reveal only where they explain the product. Trigger them with the observer's one-time `is-visible` state; use natural ease-out curves. Target text at 400–600ms, the main visual at 600–900ms, secondary UI at 300–500ms and stagger related elements by 100–180ms. A section transition is about 500–800ms. At any moment, animate no more than 1–3 important elements; everything else stays still, and each scene has one obvious focal point. No bounce, spin, excessive parallax, cross-screen flying objects, excessive scaling, constant motion, simultaneous competing animation, text/video collision or overlap between entire sections. Never hide essential copy from the DOM. Under `prefers-reduced-motion`, present the complete readable story statically and disable entrance/qualifier animations and transforms. Tablet simplifies the composition; mobile uses sequential content, no forced floating desktop layout and no horizontal overflow.
